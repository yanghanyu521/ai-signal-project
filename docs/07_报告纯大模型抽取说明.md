# 报告纯大模型抽取（v0.3.0）

2026-09-02 更新。本说明替代 v0.1/v0.2 中“报告规则提取 + 可选 DeepSeek 补充”的设计；旧文档及历史结果保留原始记录。

## 现在如何提取

1. 用户上传报告并指定目标样本/家族，可提供别名线索。
2. 本地解析报告，保留正文顺序、段落编号、章节和页码。
3. 首次请求将全部解析正文、目标信息和完整字段 Schema 交给大模型。不执行旧事件发现、名称窗口、关键词打分、14000 字符筛选或 5000 字符固定分块。
4. 模型直接输出目标事件字段：身份、时间、状态、样本/IOC、归因、目标、AI 参与、工具链、Prompt、代码文体、行为、结果、局限及证据。
5. 独立请求再次读取全文，检查目标归属、断言强度、字段语义及遗漏；强制逐事实对象主体覆盖、高风险字段断言覆盖和五组完整性检查。若模型识别有证据却遗漏对应字段，则拒绝并反馈修复。
6. 最终模型只选择原文段落编号，后端复制原段落为证据，执行结构与引用校验，计算ID/哈希；推测确定值保护性降级并审计。身份引用须包含用户目标名/用户别名，不接受模型自造别名冒充目标。校验合格后入库，仍标记 `needs_review`。详见 `09_报告抽取问题分级与主要修复_20260902.md`。

样本侧原有静态规则分析保持不变，恶意样本文件不发送给模型。报告原文里已有的代码、提示词或 IOC 属于报告正文，会随报告外发；请确认报告适合交给配置的服务处理。

模型由 `src/ai_signal_hub/report_llm.py` 调用。旧 `报告信息抽取` 项目只复用文档解析、字段契约及交叉比较器，不调用其规则提取入口，不修改旧项目。

## 全文与超限策略

- 默认尝试全文，不使用字符数作为内容筛选预算，也不固定限制为 30 条声明。
- 仅服务端明确上下文/请求容量超限，或响应 `finish_reason=length` 时，才按正文顺序拆分重试。
- 分块优先沿段落边界；单个特大段落可拆分，边界保留少量原文重叠。每个子请求仍带目标、章节和字段契约。
- 所有正文都进入提取与最终全文复核后才保存结果；初次Schema问题可经全文复核修复，最终失败则整份不入库。不会把部分结果伪装成完整报告。
- 合并后的全文复核若超容量，明确失败，不跳过全局语义检查；可调整输出预算/模型后重试。
- 标量结论冲突时不静默覆盖：填 `unknown/null`，在 `conflicts`、`limitations` 保留不同结论，待人工核查。
- 全覆盖指“解析出的文本均已送入模型”，不代表模型特征召回率为 100%。跨块指代、未知事实、图片及扫描件内容仍可能漏抽；当前没有新增 OCR/图片理解。
- 默认最多 32 次 HTTP 请求（包括重试），每次连接/读取超时 240 秒，最多 3 次瞬时故障尝试；达到上限明确失败。当前 API 同步执行，一份报告至少提取+复核两次请求，可能超过前端等待时间，应使用 API 客户端设置足够的读取超时。

DeepSeek 的 JSON 输出需要指定 JSON 模式、提供格式要求，并防止输出截断；新管线按官方说明设置请求并拒绝空内容/残缺结果。[官方 JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)

## 服务端配置

环境变量必须配置在启动 API 的进程环境中，前端不接收密钥。

| 环境变量 | 用途 / 默认值 |
|---|---|
| `DEEPSEEK_API_KEY` | 首选密钥变量 |
| `cc-api` | 兼容原项目密钥变量；仅首选变量不存在时使用 |
| `DEEPSEEK_BASE_URL` | 默认 `https://api.deepseek.com`；支持根地址、`/v1` 或完整 `/chat/completions` 地址 |
| `DEEPSEEK_MODEL` | 默认 `deepseek-v4-flash`；显式指定的模型名称不被改写 |
| `REPORT_LLM_MAX_OUTPUT_TOKENS` | 每次最大输出额度，默认 `32768`，为思考及JSON预留空间，不是输入字符预算 |
| `REPORT_LLM_TIMEOUT_SECONDS` | HTTP 超时，默认 `240` 秒 |
| `REPORT_LLM_MAX_REQUESTS` | 每份报告最大请求次数，默认 `32` |
| `REPORT_LLM_THINKING` | DeepSeek v4默认`enabled`，可显式设`disabled`；建议保持启用 |
| `REPORT_LLM_REASONING_EFFORT` | DeepSeek v4思考强度，默认`low`，支持`low/high/max`；high实测可能耗尽额度 |

默认型号更新依据：官方已公告旧 `deepseek-chat/deepseek-reasoner` 于 2026-07-24 停用。[官方公告](https://api-docs.deepseek.com/news/news260424/) 若兼容代理使用自定义模型名，显式设置 `DEEPSEEK_MODEL`；平台不会覆盖该配置。V4模型现在默认思考模式low，启用时不发送无效的temperature参数；只保存最终结构，不保存思考内容。[官方模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)

输出额度应按实际模型/代理支持范围配置，不把某个固定数字宣称为所有模型的上下文上限。鉴权失败、接口不支持、超时、非法 JSON 或证据不合格都会报错，绝不降级到规则提取。

## API 与兼容性

`POST /api/v1/reports/analyze` 和 `POST /api/v1/analysis-cases` 路径不变。

- 新调用只需上传报告并指定 `target_name`，不必再传 `use_llm`。联合分析仍可从案例样本家族推导目标。
- 兼容参数 `use_llm` 默认 `true`；新报告显式传 `false` 返回 `400`，不会偷偷外发旧客户端原本要求离线处理的报告。
- 仅分析样本、复用已有报告、交叉验证历史结果均不要求密钥，也不重新调用大模型。
- 缺少密钥/鉴权或配置错误返回 `503`；模型接口/响应/证据错误（含身份引用未能证明目标）返回 `502`；模型确认无目标返回 `400`。
- 联合案例的报告步骤失败时标记 `report_analysis_failed`，已分析样本及历史资料保留，可在同一案例补传重试。

例如，已在服务端配置密钥后：

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/v1/reports/analyze -F "file=@report.html" -F "target_name=PROMPTFLUX"
```

事件字段仍沿用 Schema 0.3，兼容现有知识库、交叉验证与展示；平台结果的 `extraction` 扩展审计元数据包括：

- `mode: llm_only`、`rule_extraction: false`。
- `target_event`、`target_event_only`。
- `input_strategy: full_text / full_coverage_chunks`。
- `coverage`：解析段落数、字符数、遗漏段落数、完成块数。
- `model_requests`、`splits`、`conflicts`。
- `quality_review`：主体与高风险字段断言、组级完整性检查、质量问题、保护性降级、身份原文锚点、证据原段复制策略、可验证ID前缀/日期修复审计；当前质量版本1.3。

报告运行目录保留 `blocks.json`、`llm_response_N.json`、`llm_merged_candidate.json`、`llm_review_N.json`、必要时的`llm_review_error_N.json`、`llm_audit.json`及成功的`report_events.json`，不写入API密钥。证据和模型复核仍不能保证理解与归属一定正确。

## 历史数据和测试

本次不自动重跑历史知识库，不修改已有统计，也不删除原报告。重新上传报告时才走新管线；选择已有报告继续使用其原始分析结果。

自动化测试通过模拟 HTTP 模型响应验证实际解析、字段校验、入库与交叉验证；不调用真实模型，不发生真实模型费用。测试不等于已完成真实报告抽取质量评估。实际使用前需配置密钥并启动 API；更新已经运行的 API 则需重启。
