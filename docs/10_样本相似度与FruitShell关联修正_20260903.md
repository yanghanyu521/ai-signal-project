# 样本相似度与FruitShell关联修正

日期：2026-09-03。算法版本：`ai-signal-evidence-pairwise-v2`。

同日后续更新：FruitShell上游静态提取规则已补齐并完成隔离复测，见[规则修补与验收](11_FruitShell静态规则修补与验收_20260903.md)。本文中的空特征/34簇等为相似度修订阶段的历史库快照；后续规则复测未覆盖这些正式记录。

## 结论与本轮范围

FruitShell没有显示近邻不是聚类距离阈值导致的。修复权重被缩放抵消、占位特征被放大、跨语言/低质量代码统计直接比较、Prompt模糊哈希未真正比较距离、缺失值混为零分等问题。

本轮只读取已有结构化样本结果，不执行/重新分析恶意样本，不调用报告大模型，不将报告中的描述补成样本静态命中。原始样本、报告、案例、交叉验证等记录不变，仅重算三张派生聚类/关系表。

## 1. FruitShell为什么没有关联

库内样本`f8f5e0440c57c7deffd75ca33e2511867039796aa803e7ef847396a379188a7d`：

- 元数据为ASCII text，language=null，recoverability=unknown。
- 已保存的工具链证据、Prompt证据、代码统计指标三个组均为空。
- 旧库中实际存在44条样本对关系，但全部总分为0；接口只显示大于0.000001的关系，故显示空列表。
- 旧聚类为单成员簇，0.45距离阈值只决定是否同簇，不参与近邻列表过滤。

## 2. 三组评分

### 工具链：标准化事实的加权Jaccard

保留厂商、模型家族、具体模型、SDK、端点、AI CLI等事实，统一大小写、同值去重。不再把“命中同一个通用规则”或“同为model_identifier类型”本身当作共同工具链。

事实权重：vendor=1，family=1.5，model=2，SDK=1，endpoint=1.5，AI CLI=1。标准化provider与vendor合并为同一厂商维度；端点去掉用户信息、查询参数和fragment。现有分类结果也按相同维度去重，不重复加分。

公式：`Σ min(左事实权重, 右事实权重) / Σ max(左事实权重, 右事实权重)`。任一侧没有可用事实时返回null；两侧都有事实但无交集时为0。

仍是已有静态候选证据之间的比较，不是重新验证工具链命中是否真实；字段别名和提取质量仍会影响结果。

### Prompt：真实哈希距离、一对一匹配和结构信息

1. 精确SHA-256支持带前缀与历史裸摘要；必须是完整合法摘要，不截断。
2. 支持现有`fuzzy_hash={algorithm,value,...}`格式，以及明确`simhash64:`前缀的历史字符串格式。只接受已知算法，忽略无效/不支持/空令牌零哈希，不把整个字典转字符串当特征。
3. 逐对比较：精确哈希相同得1；否则计算64位SimHash的Hamming距离。距离d≤8时得`0.95×(1-d/16)`；d>8得0。随机哈希约32位差异不再得到50%“相似度”。
4. 对两个样本的去重Prompt集合做一对一最大总分匹配，内容分为匹配总分除以较大集合大小；同一Prompt不能重复匹配多个对象抬高分数。
5. 结构只使用明确true标志与特殊Token（兼容旧字段`token`/`value`）；共同false不算证据，结构用加权Jaccard。
6. 两边都有可比较内容和结构时，Prompt分为`0.8×内容分+0.2×结构分`；只有内容可比较时用内容分；只有结构可比较时最多`0.2×结构分`。两者都不可比较则为null。

记录匹配方法、Hamming距离、匹配索引、内容分/结构分及匹配强度。索引相对于按哈希排序并去重的两侧集合，`source_sample_id/target_sample_id`明确左右对象，不随查询方向变化。不给截断的text_preview做全文或语义比较。

上述SimHash阈值和结构权重是保守工程初值，未经过独立标注集校准；这是模板/结构相似性，不是大模型语义相似度。

### 代码统计：先可比性检查，再比较数值差异

- 只比较同一已知语言、`original_source`且没有parse_error的源码；Python还需要AST指标。
- PE仅字符串、未知语言、恢复/反编译文本、解析失败均标为不可比较，不显示成0%或高相似度。恢复层原指标保留，但不冒充原作者风格。
- 行数、函数数、平均标识符长度、空行/注释/异常处理比例逐项使用`min(x,y)/max(x,y)`；共同为0的项目不作为相似证据。
- 命名风格与AST节点分布分别归一化后用加权Jaccard，各算一个分量，避免大量AST计数维度挤占其余指标。
- 至少有3个有效共同分量才评分；对有效分量并集取平均，一侧缺失分量贡献0。不使用对数压缩、余弦方向或全库最大值。
- “共同特征”只列真实共同事实/Prompt匹配或相等的代码统计分量，不再把两边都有loc字段当作数值相同。

这些仍是代码统计，不是代码功能/同源/AI生成概率。非Python指标仍受旧正则提取器限制；历史original_source来源标签也可能需要单独审计。

## 3. 综合分数和聚类

`总关联分 = 0.5×工具链分 + 0.3×Prompt分 + 0.2×代码统计分`

不再拼接后做全库列缩放，也不生成`fallback:<样本哈希>`虚构维度。权重真实生效，已有样本对的分数不因加入无关样本而改变。

缺失组对总分贡献0，但其API分项值是null，不重分配权重；另外返回`comparable_weight`说明可比证据覆盖的权重。没有任何可比组时总分也为null。`conditional_similarity=总分/可比权重`仅作诊断，不参与聚类或候选排序，避免证据稀少的样本被重新放大成高总分。

整体聚类仍只有一套：平均连接的凝聚层次聚类，输入预计算距离`1-总关联分`，对角线为0，无法比较的不同样本距离为1。默认距离阈值0.45保持不变；空证据样本因此各自为单成员簇。它不是简单的“两两分数大于55%就合并”，更不意味着同一簇有真实同源性。

三个分项仍分别解释，不生成三套独立聚类。原阈值没有因新分数含义变化而偷偷调参，后续应使用标注数据校准。

## 4. API与界面

接口不变：`GET /api/v1/samples/{sha256}/associations`。

- `limit`：1～100。
- 新增`include_unmatched`，默认false；true返回零分/不可比较样本对及原因。
- 增加`association_status`、`message`、`association_summary`、`feature_availability`、`run`。
- 每对含`comparison.groups`、权重、贡献、可比权重覆盖率、方法及具体匹配依据。
- 分项/总分可能为null，调用方必须兼容；null与0不能混用。
- 旧算法没有诊断的结果标为`legacy_results`，提示重建，不伪装成新算法。

界面使用原生表格显示可比性、精确百分比和说明；代码列改名“代码统计”，提供查看零分/不可比较结果开关和样本对评分依据。Streamlit技能指导了缺失值展示和列格式，不使用CSS或自定义组件。

SQLite仅对三张派生表新增`details_json`，兼容原有NOT NULL数值列。不可比较分数在旧数值列里保存0作为存储兼容值，以details中的状态为准；API投影为null。直接查询数据库的调用方不能只读旧数值列。提交新关系在单一事务内进行，并核对计算时的样本快照；并发修改或写入失败不会清空已有关系。

## 6. 备份、应用和运行

本轮产物：`data/evaluations/20260903_similarity_v2_final/`。

- `knowledge.before.db`：SQLite一致性备份，包含原始记录和旧派生关系。

- `manifest.json`：新旧数量、原记录指纹、算法源码指纹、FruitShell诊断。
- `comparisons.json`：990对新旧分数与新解释。
- `applied.json`：正式应用结果与应用后保护记录指纹。

先在副本验证，再通过脚本的apply命令仅替换正式库中的派生表。若生产库、预览库或算法在预览后变化，脚本拒绝应用，要求重新预览。备份和历史开发批次不覆盖。

```powershell
.\.venv\Scripts\python.exe scripts\rebuild_similarity.py preview --batch 新的批次名
.\.venv\Scripts\python.exe scripts\rebuild_similarity.py apply --batch 新的批次名
```

这两个命令不运行恶意样本、不调用模型。需要回滚时从备份恢复旧派生关系；不要直接覆盖整个数据库，以免丢失之后新增的样本/报告。

API进程需要重启加载新后端；Streamlit页面可刷新加载。交付时已询问重启许可但尚未收到确认，因此没有重启8000端口上的API。只读请求确认现进程仍不返回新版诊断字段。新前端检测此状态时提示重启并禁用重建按钮；直接调用旧API的重建/分析入口仍可能重新写入旧算法结果，重启前请勿触发这些操作。
