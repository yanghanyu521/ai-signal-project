## 2. 新静态分析闭环

新流程接在现有上传API内：旧静态提取和恢复完成后，建立统一材料索引；APK/DEX 或 PE/ELF 先由 Docker 内的 JADX/Ghidra 补充反编译材料，再由 DeepSeek V4 按上下文上限分批初筛，允许模型请求有限的索引查询，并对所有返回事实进行确定性引用核验；最后才统一分类、入库和重建关联。

样本模型只能调用 `get_unit/get_callers/get_callees/get_definitions/get_references/search_units`。未知查询、未知单元ID、任意文件读取和Shell请求会被拒绝。模型返回的 `raw_value` 必须逐字存在于所引用材料，否则进入 `rejected_facts`；SDK厂商不会自动填入模型厂商。无模型、超时、坏JSON或坏引用不会清除原有确定性结果。

样本模型默认启用并复用报告抽取的 DeepSeek V4 配置。密钥按 `SAMPLE_LLM_API_KEY`、`DEEPSEEK_API_KEY`、`cc-api` 的顺序读取；`SAMPLE_LLM_BASE_URL/MODEL` 是样本专用覆盖项，未设置时读取 `DEEPSEEK_BASE_URL/MODEL`。不设置单次分析的总 token 预算，`SAMPLE_LLM_MAX_INPUT_TOKENS` 仅限制每次请求上下文，材料自动批处理；最大请求数和超时仍保留为故障保护，触发时明确返回 `partial`。

### 结构化示例

无害测试夹具把词典外型号放在模块配置中，在另一函数构建输入，再由第三个函数调用客户端。材料索引生成配置单元、函数单元和调用/定义关系。模型返回候选后，后端只接受能回查原文的值：

```json
{
  "fact_id": "fact:<稳定摘要>",
  "signal_group": "toolchain",
  "raw_value": "nebula-not-in-rules",
  "normalized_value": {
    "model_identifier_raw": "nebula-not-in-rules"
  },
  "source_unit_ids": ["unit:<配置单元ID>"],
  "verification_status": "location_verified",
  "semantic_review_status": "needs_review",
  "role": "application",
  "limitations": []
}
```

`invented-by-model` 这类不在材料中的返回会以 `raw_value_not_in_material` 拒绝。跨块关系能指出 `send → build_payload → MODEL_ALIAS/PROMPT配置单元`；当前关系是有界AST符号与调用关系，不宣称覆盖反射、动态导入或运行时配置。

## 3. 实际支持矩阵

| 输入 | 当前真实材料 | 状态与限制 |
|---|---|---|
| Python源码 | 模块、函数/类、顶层配置、常量及有界调用/定义关系 | 已实现并有自动化集成测试；反射、动态值和跨模块复杂数据流保持未知 |
| JavaScript源码 | 原文、函数/模块词法块 | 已实现LLM入口；当前无AST/xref/dataflow，状态为partial |
| PowerShell源码 | 原文、函数/模块词法块，并保留原有规则增强 | 已实现LLM入口；当前无完整AST/xref/dataflow，状态为partial |
| ZIP/PyInstaller类归档 | 有界成员盘点；`.py/.js/.ps1`路由源码材料，DEX/原生成员提取有界字符串；保留成员来源 | 已实现基础材料；限制128成员、单成员2 MiB、总展开16 MiB和压缩比100；不递归执行/解压到磁盘 |
| APK/DEX | 原有DEX字符串/Prompt材料，加 JADX 反编译 Java 方法、类结构/常量 | Docker 镜像 `ai-signal/jadx:1.5.6` 已用官方无害 `hello.dex` 验收；方法边界来自反编译文本词法解析，名称与布局不代表作者源码 |
| PE/ELF | 原有静态字符串，加 Ghidra 函数伪代码、地址、调用名、字符串引用和导入表 | Docker 镜像 `ai-signal/ghidra:12.1.3` 已用无害 ELF 验收；伪代码/Xref可能不完整，不执行样本 |
| 其他未知二进制 | 有界静态字符串材料 | 无函数/xref/dataflow，状态为partial或unsupported |

因此，P0、源码侧P1及 Docker 反编译入口已经落地。无害实测中 JADX 生成 14 个统一材料单元（含方法级单元），Ghidra 生成 111 个函数/字符串/导入材料单元；这些数字仅证明集成链路，不代表对任意 APK/PE 的恢复率。容器全程 `--network none`，样本只读挂载，且设置 CPU、内存、PID、capability 与超时限制。
