# 统计口径、关键特征展示与逻辑审计

## 本次完成

- 将当前业务口径固定为全球 AI 安全事件 25 个，其中有样本、可分析事件 9 个，暂无样本事件 16 个；对应 9 个样本家族、45 个样本。
- 看板和报告模板不再把数据库 `events` 物理行数当成全球事件数。历史调研记录、报告事件证据与业务事件总量分别展示。
- 关联分析和交叉验证优先展示模型厂商、模型家族、具体模型与提示词正文，字段名统一为中文。
- 报告披露提示词原文时显示原文；报告仅描述提示词时明确标注“未披露原文”，展示对应报告证据片段，不把摘要伪装成提示词。
- 联合摘要突出相关组织与国家/地区。前端支持人工修订，修订值写入独立知识库表并永久覆盖展示值，模型抽取原值继续保留用于审计。

## 已修复的主要逻辑问题

| 级别 | 问题 | 修复结果 |
|---|---|---|
| P1 | 29 条数据库事件记录容易被误读为全球事件总数 | 新增知识范围指标，主统计显示 25/9/16，物理记录单列 |
| P1 | 联合摘要未返回提示词正文，前端只能显示数量和结构 | 样本返回实际提示词；报告返回原文或证据片段及可用性 |
| P1 | 组织、国家/地区无法人工补充，刷新后丢失 | 新增独立人工覆盖表与 PATCH API，永久写回 |
| P1 | 重复查看交叉验证会新增重复行并抬高统计 | 同一“样本—报告—事件”改为幂等更新，统计按对象去重 |
| P2 | 前端直接展示英文 JSON 字段和算法标识 | 主展示改为中文特征名；完整 JSON 仅保留在审计折叠区 |

正式库迁移前有 22 条交叉验证执行记录，按对象去重后为 12 个。历史重复行未删除，以保留审计历史；后续重复复算会更新同一对象，不再继续增长。

## 当前仍需注意

- 25 个全球事件目前是汇总业务指标，不是 25 条都带发生日期的结构化事件记录，因此不能据此计算可信的全球逐月增长。当前月度图只展示已收录且有日期的数据，并明确标注来源。
- 现有报告提示词记录均为“仅描述、未披露原文”。界面能够显示相关证据片段，但无法还原报告没有给出的提示词正文；需要后续报告或人工资料补充。
- 事件原始 ID 当前由上游报告产生；若未来接入多个来源且复用同一 ID，需要进一步做来源命名空间迁移。现库未发现跨来源 ID 冲突。

## 验收结果

- 正式库统计：25 个全球事件、9 个可分析事件、16 个暂无样本事件、9 个样本家族、45 个样本。
- 正式库事件物理记录 29 条；交叉验证 12 个去重对象、22 条历史执行记录。
- 正式库人工覆盖表初始化为 0 条，没有擅自填入组织或国家/地区。
- 全量自动化测试通过；测试只使用脱敏夹具，没有执行恶意样本，也没有调用外部模型。
