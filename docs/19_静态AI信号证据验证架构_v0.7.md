# 静态 AI 信号证据验证架构 v0.7

## 1. 整改范围与结论

本轮只整改恶意样本侧静态 AI 信号提取，不改报告抽取流程，也不引入动态执行或沙箱。审查指出的四项 P0 问题均存在：LLM 位置命中可影响归因、LLM 自报 role 被信任、Python 变量可能跨作用域污染、样本远端外发默认开启。多轮查询、Ghidra/JADX 可查询关系、Prompt 组成、代码观察落库、覆盖率语义、评测集和 CI 等 P1 问题也存在。

最终判定链路为：

```text
规则/结构/LLM候选发现
  → 原文位置验证
  → 静态调用或数据关系验证
  → 分析单元主体角色验证
  → attribution_eligible 门禁
  → 最终 llm_involvement / model_attribution
```

LLM 只负责提出候选和受限查询。仅 `location_verified` 的模型名、Prompt 或代码观察不能影响最终归因；只有 `role=application`、关系已验证且 `attribution_eligible=true` 的工具链或 Prompt 证据才能进入归因。`runtime_observed=false` 始终保留，静态结论不表述为运行时调用事实。

## 2. 已完成

- Python 工具链与 Prompt 恢复共用 `PythonStaticGraph`，区分模块/函数作用域，支持参数、return、2—4 层 wrapper、简单拼接/f-string、字典/列表、分支联合；未知调用停止传播。
- Fact 增加 `verification.location/relation/role`、`role`、`proposed_role` 和 `attribution_eligible`。LLM 的 role 只保存在 `proposed_role`，实际 role 来自当前材料单元。
- 依赖、example 和 analyzer directive 不进入样本 AI 使用归因；分析器定向指令单列在 `classification.analysis_targeting`。
- 语义分析支持最多四轮受控补查，查询、上下文单元和请求数均去重/限额，`query_audit` 记录每轮来源单元、参数、结果单元和拒绝原因。
- JADX 的方法调用/字符串归属及 Ghidra 的调用/被调用/字符串交叉引用均解析为 `unit_id`；无法解析的外部符号单独存入 `unresolved_calls`。
- Prompt 结果新增 `features.prompt.compositions`：按目标调用单元聚合静态组成部分，记录组件数量、未知组件数、静态重构和限制；固定 `runtime_complete=false`。相似度只允许组件对组件、完整模板对完整模板。
- `code_observation` 保存到 `features.code_generation_signals.observations`，固定不能参与模型使用或生成模型归因。
- 覆盖率拆为 `recovery_coverage`、`material_coverage`、`relation_coverage`；旧的 indexed/screened/failed 字段继续保留以兼容已有消费者。
- 默认外发策略改为 `ALLOW_REMOTE=false + local_only`。远端必须双重显式开启；`remote_redacted` 对密钥、token、密码、credential 和私钥块使用单向哈希占位符，运行结果在 `features.static_analysis.run.llm_transfer` 记录目标、远端状态、策略和脱敏计数，不保存明文映射。

## 3. 数据契约与兼容

结果版本升级为 `0.3`，Schema 同时接受 `0.1/0.2/0.3`。所有新字段均为增量字段，原有 API 路径、工具链、Prompt 和代码文体字段不删除；历史 JSON 可继续读取。历史结果不会自动获得新的关系、role 或 PromptComposition，需要通过现有重新分析 API 在本地原始样本仍存在时显式重算。

Fact 的归因相关最小结构：

```json
{
  "signal_group": "toolchain",
  "raw_value": "private-deploy-v7",
  "source_unit_ids": ["unit:..."],
  "verification": {"location": "verified", "relation": "verified", "role": "verified"},
  "role": "application",
  "proposed_role": "application",
  "attribution_eligible": true
}
```

PromptComposition 不代表实际运行时序列化后的完整请求：

```json
{
  "target_call_unit_id": "unit:...",
  "component_count": 2,
  "unknown_component_count": null,
  "call_binding": "relation_verified",
  "runtime_complete": false,
  "completeness": "static_components_only"
}
```
