# 仅脚本范围与样本侧 LLM 提取整改（v0.9）

日期：2026-11-12

## 背景与范围决策

用户需求收敛为：只分析**脚本文件**中的 AI 工具链与提示词特征，不再分析二进制文件；以 19 个真实恶意脚本的人工分析结果为基准，检验并优化大模型提取的准确率。

19 个样本范围（原表 25 个脚本中的 19 个，6 个无 AI 信号的纯脚本移出分析范围，仅作负例登记）：

- LAMEHUG×5、MalTerminal×8、QUIETVAULT×1、SLOPOLY×1、FRUITSHELL×1、PROMPTFLUX×1、PhantomRaven×2
- 其中 13 个可确认 AI 调用、2 个混淆不可静态确认（3afbb9fe6bab / 4ddbc14d8b6a）、1 个仅分析器注入（FRUITSHELL）、3 个 LLM 辅助开发无 AI 调用（SLOPOLY、PhantomRaven×2）

## 一、人工基准数据集 `evaluation/script_baseline/`

逐行人工阅读 19 个真实样本形成，每条结论带文件内行号证据：

- 7 个家族 JSON：toolchain（SDK/端点/模型/认证/参数）、prompts（分类/文本或解码文本/用途）、behavior_summary、network_indicators、`extraction_expectations`（must_find / must_not_claim）
- 近重复变体用 `same_as` + `differences_from_reference` 继承基准，不重复标注
- `report_side.json`：报告侧特征及与样本侧的预期交叉验证关系（组织/国家/时间只允许 complements）
- `README.md`：评分口径与已确认的分析师表格勘误（b64 提示词归属 ae6ed1721d37、c1a8 的 Fernet 未加密提示词、4c73 提示词为 4 条、854b 型号为 gpt-3.5-turbo 等）

基准只含特征与证据位置，不含恶意代码本体；原始样本在仓库外。

## 二、仅脚本范围门禁

- `src/ai_signal_hub/script_scope.py`：扩展名白名单（py/ps1/js/vbs/sh/bat/php 等）+ 内容嗅探（NUL/UTF-8/shebang/脚本关键字），支持无扩展名脚本（FRUITSHELL 即无扩展名）
- `services.py`：上传与重分析入口拒绝二进制/文档/压缩包，报 400；历史二进制样本结果保留不删
- `main.py`：analyze_sample / reanalyze_sample 增加 ValueError→400 映射
- 原二进制容器恢复测试改为断言拒绝（tests/test_prompt_recovery.py 末例）

## 三、样本侧 LLM 提取与确定性校验

- `static_analysis/llm.py` 新增 `script_extract` 任务与专用系统提示词：要求 ai_calling（true/false/unknown）、toolchain、prompts（含 base64 解码、拼接还原、analyzer_injection 专类）、obfuscation、llm_assisted_dev_signals、notes，所有结论必须带行号 + 精确摘录证据
- `static_analysis/script_extract.py`：
  - `build_chunks`：带行号的全覆盖分块（默认 60000 字符/块），不排序不丢弃
  - `verify_extraction`：**精度由确定性校验兜底**——证据摘录必须能在源码定位；base64 提示词必须可解码且与 decoded_text 一致；ai_calling=false 时不接受工具链条目；工具链全部失锚时 ai_calling 降级 unknown；非法分类改 other；多片段提示词文本未逐字命中时标记 verbatim_verified=false
  - `extract_script_features`：合并多块结果、提示词去重、记录传输策略与验证审计
- `legacy.py`：在确定性分析之后追加 `_run_script_llm_extraction`，结果写入 `features.llm_script_extraction`；未配置/被策略阻断/模型失败都不影响确定性结果

## 四、基准评分与真实模型运行

- `scripts/run_baseline_samples.py`：对 19 个样本逐一真实调用配置模型（不执行样本），结果写入 `data/artifacts/samples/<sha256>/result.json`
- `evaluation/run_script_baseline.py`：按基准机械可检项打分——ai_calling、型号精确匹配（gpt-3.5-turbo 与 -1106 区分）、端点、提示词召回、base64 解码一致性、混淆样本幻觉、负例误报、FRUITSHELL 注入分类；自然语言期望保留人工复核
- 配置：`.env` 中 `SAMPLE_LLM_ALLOW_REMOTE=true`、`SAMPLE_LLM_TRANSFER_POLICY=remote_redacted`（外发前脱敏硬编码密钥）；`config.py` 现在自动加载项目根 `.env`；pyproject 补声明 python-dotenv

### 首轮真实运行观察

- FRUITSHELL：ai_calling=false + 1 条 analyzer_injection，正确识别注入且未报工具链
- MalTerminal 4c73：ai_calling=true、型号 gpt-3.5-turbo-1106 精确、4 条提示词分类与基准完全一致，验证零违规
- LAMEHUG 384e：2 条工具链（Qwen + flux-dev）、4 条提示词（含图像提示词与负面提示词），与基准一致

### 运行中完成的校验器/评分器迭代

1. 校验器不再因"摘录只是长 base64 的片段"误杀：定位源码中完整 base64 段解码比对；摘录失准时用 decoded_text 重编码回证（含引号/空格变体）；明文提示词在摘录失准但原文命中时采信并记警告
2. 评分器文本归一化兼容源码转义（`\\` 与 `\n`/`\r` 字面量）
3. 基准自纠错：ae6ed 的 p2 解码文本应为 "office and pdf/txt"（人工转录笔误，以源码解码为准修正）
4. 前 16 个样本评分全部通过（16/16 clean，finding_counts 为空）

### 最终真实运行结果（DeepSeek，remote_redacted 脱敏外发）

- 19/19 样本提取完成、19/19 通过基准机械检查（finding_counts 为空）：型号精确匹配、端点、提示词召回、base64 解码一致性、混淆样本零幻觉、负例零误报、FRUITSHELL 注入分类正确
- QUIETVAULT：3 条 AI CLI 工具链 + file-search agent 提示词；其源码 `ASCII/UTF‑8` 含 U+2011 非断行连字符（LLM 生成文本特征），模型逐字保留，评分器增加 Unicode 连字符归一化
- PROMPTFLUX：74 个全覆盖分块约 16 分钟，gemini-1.5-flash-latest 端点与自我再生提示词正确提取
- 混淆两样本（3afb/4ddb）与 SLOPOLY、PhantomRaven 均未报出任何工具链/提示词，符合基准

全量评分结果见 `evaluation/script_baseline_metrics.json`（运行产物），UI"基准评估"页可直接查看。
