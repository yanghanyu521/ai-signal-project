# AI Signal Project v0.8 整改与 45 样本评估

日期：2026-10-12。工作分支：`feat/v0.8-dual-path-stylometry`；未合并 `main`。

## 1. 整改范围与方法

本轮保持既有架构和三类特征：AI 工具链、Prompt、AI 生成代码文体指纹；不改报告侧，不运行恶意样本。先完成 P0 和人工金标准工具，再完成 P1。复测使用原有 9 家族、45 个样本的相同 SHA-256，比较 v0.7 规则、v0.7 完整 LLM、整改前 v0.8 与整改后 v0.8。四组各有 45 份结果文件，SHA 对齐检查通过。

P0 已实现：二进制多编码字符串、PE 资源、APK/DEX 字符串恢复及分批送模；材料发现、保留、扫描和送模覆盖计数；未知模型/SDK/私有接口候选与“语义确认”“静态调用验证”分级；阻止仅凭 LLM 自报的 `model_argument` 升级；程序 Prompt、越狱 Prompt、分析器注入和普通文本分型。Python 3.11/3.12 CI 及 A–K 合成评估已跑通。

P1 已实现：Python 最近赋值与分支数据流绑定；源码、注释、嵌入 Prompt、数据的文体材料区分及多批覆盖；LLM 新发现 Prompt 参与候选相似度与 instruction profile；规范化 AST 结构指纹与结构统计哈希分离。文体相似度不作为生成模型身份结论。APK 字符串 JSONL 中 Unicode 行分隔字符造成的解析失败也已修复，并加入回归测试。

## 3. 待人工复核与不能验证的部分

已在私有目录生成去重候选队列 606 条，涉及 37 个 SHA；其余样本目前没有进入候选池的记录。标注模板要求两人独立判定真实 AI 特征、静态调用、Prompt 角色和已知/未知模型，再进行冲突裁决，支持 `uncertain`。独立漏检流程核对了 45 个原始 SHA，发现约 1,427,417 个未命中区域，只抽取其中 6,592 条供复核；另有 1,729,083 条字符串因漏检扫描上限未进入该检查。因此漏检审计为 `complete=false`。

当前**没有人工裁决金标准**：工具链/Prompt 的正确数、漏检数、Precision、Recall、F1，静态调用正确/错误升级和 LLM 文体标签准确率均为待评估，不能用零值代替。即使候选池标注完成，在独立漏检尚未穷尽时也只能报告“候选池 Recall/F1”，不能宣称完整 Recall。45 个样本没有已知代码生成模型来源真值，不计算模型身份识别准确率。

仍不能确认：未考虑的 APK 成员、被丢弃的二进制字符串及运行时构造的调用路径中是否有漏检；同进程/`ast.unparse` 测试不能替代跨平台或外部格式化鲁棒性测试。HTTP 402 的外部服务条件恢复后，须只补跑 5 份不完整结果、重新生成比较与审计，再进行人工双标和裁决。补跑前不得将本报告视为完整 45 份 LLM 成功分析结论。
