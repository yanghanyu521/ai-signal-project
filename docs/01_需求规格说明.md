# 需求规格说明（v0.1）

## 1. 项目目标

建设一个面向 AI 参与网络攻击研究的统一工作台。用户可以提交恶意样本和安全报告，获得相互独立、可回溯、可交叉验证的结构化结果，并把结果持续沉淀为本地知识库；系统按统一口径提供全局统计和自动报告。

## 2. 角色与核心场景

首版只有本地分析员角色：

1. 上传单个恶意样本，获取静态 AI 信号、模型归因、Prompt 和代码文体候选特征。
2. 上传样本对应或相关的报告，将一份报告拆成一个或多个事件，并提取报告证据。
3. 指定样本和报告事件，查看支持、冲突、补充和无法判断的字段。
4. 新样本分析完成后，按 SHA-256、模型、家族、Prompt 哈希和事件关系查询知识库。
5. 随时查看本地知识库的事件、样本、报告、分析覆盖、模型分布和按月增量。
6. 选择时间范围并生成已填充的统计报告。

## 3. 功能需求

### FR-01 样本上传与静态分析

- 支持最大 100 MiB 的单文件上传，先计算 SHA-256，再以哈希去重。
- 复用 `ai_signal_demo`，禁止执行、导入、调试和外传样本。
- 保存完整结构化结果和关键检索字段；分析失败也要返回可审计错误。

### FR-02 报告上传与事件抽取

- 支持 PDF、HTML、DOCX、Markdown、TXT。
- 一份报告可拆分多个事件；每个事实保留证据 ID、位置和原文引用。
- DeepSeek 是可选候选提取器，密钥只从 `cc-api` 读取，候选必须经过证据校验并标记复核。

### FR-03 关联与交叉验证

- 优先使用 SHA-256 精确关联；家族名只能作为候选关联。
- 输出 `supports / contradicts / complements / inconclusive`，保存双方字段路径、值、报告证据 ID、关联方法和复核状态。
- 交叉验证不修改样本结果和报告结果。

### FR-04 本地知识库

- 结构化保存样本、报告、事件、事件—样本关联、交叉验证和生成报告。
- 保留原始 JSON 快照，防止规范化字段丢失证据细节。
- 支持导入现有 45 条样本结果和研究事件表，导入操作可重复且不产生重复记录。

### FR-05 关联分析与检索

- 支持按 SHA-256、事件名、家族、模型、发布者和自由关键词检索。
- 单个样本响应应包含直接关联事件和已有交叉验证摘要。

### FR-06 统计

- 至少提供：已收录事件、当月新增、上月新增、月环比、已分析样本、报告数、交叉验证数、confirmed/probable/unknown 分布、具体模型分布。
- 统计响应必须包含 `scope` 和 `as_of`；“全球事件”只能表述为“知识库已收录的全球事件”。

### FR-07 自动报告

- 使用可编辑模板生成 Markdown 报告并保存快照。
- 报告至少包含统计口径、执行摘要、事件月度趋势、样本覆盖、模型归因分布、交叉验证结果和局限。
- 生成报告引用的是当时的统计快照，后续知识库变化不应悄悄改变历史报告。

### FR-08 API 与测试界面

- 所有业务能力先通过 `/api/v1` API 提供；OpenAPI 是接口契约。
- Streamlit 界面只调用 API，用于上传、检索、看板和报告生成测试。

## 4. 非功能需求

- 安全：默认仅监听本机；上传大小限制；原始样本不进 Git；禁止路径穿越和文件名直用。
- 可审计：每项结果有时间、版本、来源、哈希和原始 JSON。
- 可移植：数据目录可通过环境变量配置；Windows 为首要运行环境。
- 可扩展：数据库访问集中封装，后续可迁移 PostgreSQL；分析适配器与 API 解耦。
- 性能：首版同步处理，适合测试和小批量；耗时分析的异步任务队列列入下一阶段。

## 5. 首版不包含

- 多用户、角色权限、SSO、外网部署和租户隔离。
- 分布式任务队列、对象存储、容器沙箱和动态恶意代码分析。
- 扫描 PDF OCR、复杂跨页表格和无证据的大模型自由归因。
- 对“全球所有 AI 安全事件”的自动互联网穷举；当前统计只覆盖本地收录数据。

## 6. v0.1 验收标准

- API 可启动并通过健康检查。
- 脱敏样本可完成上传、静态提取、入库和查询。
- 测试报告可完成事件抽取、入库和查询。
- 至少一个样本—事件交叉验证可保存并返回四态摘要。
- 历史样本/事件导入可重复执行且计数稳定。
- 统计接口与报告模板对同一快照给出一致计数。
- Streamlit 页面能完成关键 API 的人工测试。
