# 需求 v1 意见梳理与实现说明

## 1. 总体意见

`需求v1.txt` 指出的三个问题成立。原 v0.1 已有两类提取器和交叉验证能力，但缺少贯穿用户工作流的“分析案例”，知识库检索也只是查找而不是关联分析，统计报告的时间范围参数没有真正生效。本轮将三项需求统一为：案例驱动采集、样本相似发现、可审计统计快照。

## 2. 样本与报告对应上传

### 用户行为

- 同时上传样本和对应报告。
- 只上传样本，案例进入 `waiting_for_report`。
- 只上传报告，案例进入 `waiting_for_sample`。
- 选择已有样本并上传新报告，或选择已有报告并上传新样本。
- 选择已有案例，继续补传缺失对象。

### 数据与证据边界

- 对应关系保存在 `analysis_cases/case_samples/case_reports`，不是写回样本或报告原始结果。
- 报告包含样本精确 SHA-256 时自动选择对应事件。
- 报告只有一个事件时，可以按用户显式对应自动验证，但仍标记关联方法。
- 报告有多个事件且没有精确哈希时，案例进入 `event_selection_required`，不自动传播字段。

### API

`POST /api/v1/analysis-cases` 使用 multipart 表单，可同时包含：

- `sample_file` 或 `existing_sample_sha256`
- `report_file` 或 `existing_report_id`
- `case_id`、`title`、`notes`
- `source_case`、`canonical_url`、`use_llm`

同一侧不能同时上传新文件并选择已有对象。

## 3. 新样本自动关联与聚类

### 特征组成

- AI 工具链：规则 ID、模型厂商、模型家族、具体模型和规范化工具链字段。
- Prompt：精确哈希、模糊哈希、结构标记和特殊 Token。
- 代码文体：现有静态代码指标；仍不把 `not_trained` 状态表述为生成模型分类器。

所有 `unknown/null/—` 等占位值从聚类特征中排除，避免“共同没有证据”被误判为相似。

### 算法

- `DictVectorizer`：生成可回指的稀疏特征。
- `MaxAbsScaler + L2 Normalizer`：处理不同量纲并保持稀疏结构。
- `AgglomerativeClustering`：平均链接、余弦距离、阈值 0.45，不预设簇数。
- 工具链、Prompt、代码文体权重为 0.5、0.3、0.2。

选择层次聚类是因为当前样本规模小、簇数未知，且希望保留距离阈值和可解释共同特征。新样本分析完成后自动重建聚类并返回近邻；也可调用 `/samples/recluster` 手动重建。

### 输出解释

- 总相似度和三类分项相似度。
- 是否在同一聚类、簇编号和簇大小。
- 双方共同命中的安全结构化特征。
- 结果只表示候选关联，不表示同源、同模型或同一攻击者。

## 4. 统计报告修复

### 已修复问题

- `date_from/date_to` 现在实际传入统计查询，不再只保存参数。
- 策展事件按 `event_date` 过滤。
- 样本、报告、分析案例和交叉验证按知识库 `created_at` 过滤。
- “知识库每月增长”改用 `created_at`；“事件发生月趋势”继续用 `event_date`，两者分开展示。
- 上月为零时不输出误导性的百分比，改为显示绝对新增。
- 报告正文回显实际筛选区间并保存不可变统计快照。

## 5. v1 验收标准

- 同时上传样本和报告可建立一个案例并自动触发可行的交叉验证。
- 单侧上传后可通过原案例补传另一侧，案例状态正确变化。
- 新样本完成后自动返回聚类和非零近邻；共同特征不包含 unknown 占位值。
- 时间范围之外的样本、报告、案例和验证不进入范围报告统计。
- 自动化测试覆盖上述流程，旧功能回归通过。
