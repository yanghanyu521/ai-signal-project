# 需求 v2 答疑与实现说明

## 一、前端文字太小

已将 Streamlit 基础字号提升到 17px，并同步调整各级标题字号。界面继续使用 Streamlit 原生主题配置，没有注入易失效的组件 CSS。

## 二、联合分析与知识库更新逻辑

| 操作 | 知识库行为 | 是否新增重复对象 |
|---|---|---|
| 上传库中不存在的样本 | 静态分析后按 SHA-256 新增样本，随后重建样本关联 | 否 |
| 上传已存在的样本 | 重新分析并更新同一 SHA-256 条目的结果与更新时间 | 不新增样本 |
| 上传新报告 | 按指定样本/家族定向抽取后入库 | 按逻辑报告键去重 |
| 上传已有报告 | 复用同标题逻辑报告，合并其目标事件证据 | 不新增逻辑报告 |
| 只上传样本 | 建立状态为 `waiting_for_report` 的分析案例 | — |
| 后补报告 | 在联合分析页选择原案例，只上传报告并确认目标名称 | — |

报告的原始记录仍保留审计信息。主统计按规范化标题进行逻辑去重，因此当前 9 条原始报告记录显示为 7 份逻辑报告。

## 三、DeepSeek 语义候选补充

不开启时，系统只运行确定性规则抽取。开启后，系统会把报告中与目标事件相关的文本片段发送给已配置的 DeepSeek 兼容接口，让模型补充规则可能漏掉的实体和关系候选。

边界如下：

- 不会把恶意样本内容发送给 DeepSeek。
- LLM 输出不能直接成为事实，必须能逐项回指报告原文。
- 无法通过证据校验的候选不会合并。
- 成功合并的候选仍标记为 `needs_review`，需要人工复核。
- 该功能是可选增强，不影响基础规则抽取。

## 四、11 个事件和当前真实口径

原来的 11 条数据来自 `ai_signal_demo/week1_research/ai_attack_events.csv`，是早期人工研究表中的历史研究事件，不是当前样本家族数，也不是 9 份家族报告的去重数量。

当前知识库主口径已调整为：

- 已分析样本：45 个。
- 已标注样本家族：9 个。
- 家族—报告映射：9 组。
- 原始报告记录：9 条。
- 逻辑去重报告：7 份。
- 历史研究事件：11 条，单独展示。
- 报告目标事件证据：17 条，单独展示。

自动报告和看板不再把 11 条历史研究事件称为当前“全球事件总数”。

## 五、报告定向抽取和交叉验证

报告上传现在必须提供目标样本或家族名称，并可提供别名。平台会把目标传给旧报告抽取器，并在抽取后严格只保留目标名称/别名对应的事件；目标没有在正文中出现时返回错误，不会把报告中的其他事件归到该样本。

交叉验证页面改为先选择分析案例：

- 单样本、单报告案例自动选择两侧对象。
- 多对象案例只能在该案例内部继续选择。
- API 会校验样本和报告是否属于案例，禁止任意跨案例配对。
- 对历史全报告结果，优先按 SHA-256，其次按家族唯一匹配目标事件。

现有两个 PromptLock 待选择案例已按家族唯一匹配完成验证，每个案例得到 2 项确认、1 项补充、0 项冲突。

## 六、联合分析结果展示

联合分析结果现在默认展示：

1. 目标样本、家族和报告事件概要。
2. 样本侧与报告侧 AI 工具链对照。
3. 样本侧与报告侧提示词特征对照。
4. 已确认字段、冲突字段、证据不足字段。
5. 报告补充但样本静态分析通常无法获得的时间、攻击者、目标、AI 参与方式、关键行为、结果和限制。

完整 JSON 仍保留在“审计用”折叠区，不再作为主要结果界面。

## 七、主要新增或调整 API

- `POST /api/v1/reports/analyze`：新增 `target_name`、`target_aliases`。
- `POST /api/v1/analysis-cases`：新增报告目标字段，响应增加 `joint_summary`。
- `POST /api/v1/analysis-cases/{case_id}/cross-validate`：按案例执行交叉验证。
- `GET /api/v1/statistics/overview`：增加样本家族、逻辑报告、原始报告记录和家族—报告映射指标。
