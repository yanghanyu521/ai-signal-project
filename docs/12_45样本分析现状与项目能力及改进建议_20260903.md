## 📌 一、现阶段成果

项目已打通样本静态特征提取、报告定向大模型抽取、样本与报告交叉确认、本地知识库、样本关联和模板统计报告，并提供 API 与测试界面，已具备本地分析验证的基本能力。

- **已处理 45 个样本**，均保存了结构化静态结果。
- **35 个获得至少一组可用特征，10 个尚未获得目标特征**；这里的“可用”指通过当前关联模块的基本检查。
- 三组分别覆盖：工具链 **25 个**、提示词文本候选 **25 个**、可用代码指标 **20 个**，其中 10 个三组同时可用。
- 最近一次验收共 **168 项测试通过**；13 个重点样本的真实静态入口复验通过，已备份更新结果并重建关联。

上述数字是本批样本的处理和特征覆盖情况，不是恶意检测准确率。各组存在交集，不能相加；没有提取到特征，也不等于样本良性或永久无法分析。

### 尚无可用特征的 10 个样本

- **PromptSpy：6 个 APK。** 已有成员扫描和本轮隔离复核均未形成目标特征，仍需核实载荷内容和调用关系，不能直接归因为“没有解包”或“全部加密”。

另外，25 个样本的代码组不可用，主要是未获得可用原始源码，其中包括 3 个 Python 解析失败的样本。提取到 PE、PYC 或 APK 内的字符串，不代表恢复了原作者的代码风格；代码指标本身也不能证明由 AI 生成。

## ⚙️ 三、项目现有能力

| 模块 | 已实现内容 | 主要边界 |
|---|---|---|
| 样本静态分析 | 上传、哈希去重、工具链/提示词/代码指标提取及来源记录 | 不执行样本；不是通用反编译器，仍有未覆盖格式 |
| 报告特征抽取 | 默认大模型按指定样本或家族读取解析全文，提取事件、AI 特征与证据 | 不再用规则预筛正文；仍有语义误判、漏提及交付不稳定 |
| 样本—报告交叉确认 | 在案例内识别支持、补充、矛盾和证据不足，保留两侧原始结果 | 三组概念对齐，不是所有字段都能一一比较 |
| 本地知识库与关联 | 保存样本、报告、事件和验证结果；支持查询、相似度与聚类 | 当前收录 45 个样本、7 份逻辑报告、13 个分析案例；关联仅供复核 |
| 统计与模板报告 | 按知识库生成数量、分布、月度统计及 Markdown 报告 | 统计的是本地收录资料，不是完整全球事件总量；入库增长不等于事件发生增长 |
| API 与测试界面 | 样本/报告分析、联合分析、查询、关联、统计及报告下载接口 | 当前为本地测试原型，测试界面用于验证流程 |

主要功能均可通过 API 调用，具体路径见[API 接口清单](03_API接口清单.md)。

当前能力的判断应区分“功能已实现”和“准确性已充分验证”：报告侧仍需人工复核关键字段，样本中的模型标记也可能来自依赖或分析辅助工具，不能直接视为已确认的攻击行为。

已有 13 个重点样本结果已更新；新上传要使用最新提取逻辑，API 需加载修复后的代码。选择已有样本、重建关联不会重新提取特征。

## 🔧 四、下一步工作重点

1. **继续补齐明确缺口。** 优先处理 6 个无特征 APK、剩余 DLL 提示词及解析失败源码；ZIP、PDF、短文本先判断文件角色，再选择处理方式。
2. **验证提取准确性。** 用固定样本和对应报告逐字段复核，重点检查提示词完整性、目标归属及报告中的高风险语义判断，记录误提和漏提，而不只统计字段非空。
3. **让结果状态清楚可用。** 明确区分完整文本、静态组成部分、未发现和提取受限；提供清晰的重新分析操作，并在统计报告中标注本地收录范围和数据时间。
4. **探索基于智能体的样本分析与特征提取。** 目前样本侧依赖规则匹配与固定静态解析流程，受规则覆盖范围、复杂语义理解和上下文关联能力限制。后续考虑引入智能体，根据样本特点选择静态分析工具、追踪相关代码与调用关系，辅助提取工具链、提示词和代码特征；保留证据来源与人工复核，不执行样本。该方向尚未实现，需先验证提取效果。
