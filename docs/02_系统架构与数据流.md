# 系统架构与数据流（v0.1）

## 1. 分层

```text
Streamlit 测试界面 / 外部调用方
                 |
             FastAPI /api/v1
                 |
    +------------+-------------+
    |            |             |
样本适配器    报告适配器     知识/统计/报告服务
    |            |             |
ai_signal_demo  报告信息抽取   SQLite + Jinja2
    |            |             |
    +------ 证据快照与规范化索引 ------+
```

FastAPI 是唯一业务入口。测试界面不直接读取数据库，避免测试代码形成第二套业务逻辑。

## 2. 样本数据流

1. API 分块读取上传内容，在临时目录计算 SHA-256，并执行大小上限检查。
2. 文件移动到 `data/quarantine/<sha256>.sample`；不保留用户文件名作为物理路径。
3. 适配器调用旧项目纯静态分析器，结果写到 `data/artifacts/samples/<sha256>/result.json`。
4. 完整 JSON 作为证据快照入库；SHA-256、文件类型、语言、LLM 结论和模型字段单独索引。
5. 若知识库已有同哈希事件关联，可立即在样本详情中返回关联事件。

## 3. 报告数据流

1. 只接受白名单扩展名，按 UUID 保存到 `data/reports/<id>/source`。
2. 报告适配器调用 v0.3 事件抽取管线，输出报告、证据块、事件索引和事件结果。
3. 报告和事件分别入库，事件保留完整 JSON。
4. 事件中的 SHA-256 与样本表连接；精确哈希关系可以用于样本级验证，家族关系只能作为复核候选。

## 4. 交叉验证数据流

交叉验证服务读取一份样本结果快照和一份报告事件结果快照，调用旧项目 v0.3 比较器。返回结果作为第三份不可变记录保存，包含双方字段路径、证据 ID、关联方法、四态关系和复核状态。

## 5. 知识库数据模型

| 实体 | 关键字段 | 说明 |
|---|---|---|
| samples | sha256、元数据、模型归因、result_json | 每个哈希一条，重复分析更新快照 |
| reports | report_id、内容哈希、来源、result_json | 报告级元数据和完整事件结果 |
| events | event_id、名称、日期、类型、raw_json | 报告事件或研究事件 |
| event_sample_links | event_id、sample_sha256、方法、置信度 | 允许事件先于样本入库 |
| cross_validations | sample、event、report、summary、result_json | 独立证据对照记录 |
| generated_reports | 标题、范围、统计快照、文件路径 | 可复现的报告快照 |

## 6. 部署演进

- v0.1：本机 FastAPI + SQLite + 同步分析 + Streamlit。
- v0.2：后台任务队列、任务状态、取消/重试、批量上传、DOCX/PDF 报告导出。
- v1.0：独立分析沙箱、PostgreSQL、对象存储、认证授权、审计日志、监控与备份。
